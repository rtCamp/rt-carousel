# Handpicked Posts for Carousels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Keep work in this repository root; `rt-carousel/` is a separate, untracked checkout and is not the implementation target.

**Goal:** Let editors choose published posts/pages in a fixed order for a Query Loop carousel while preserving unchanged Latest posts behavior, existing content, and the Query Loop card design.

**Architecture:** Keep `core/query` and `core/post-template`; store `metadata.rtCarousel = { mode, ids, postType }` on the Query block (no new block type or changed saved HTML). The Query block's `query` stays intact. A scoped editor enhancement supplies a transient handpicked query to the existing Post Template edit component; a server filter makes the corresponding transient query for core rendering, then `query_loop_block_query_vars` returns only published picked IDs in order. Both paths use the same stored IDs and post type. The editor picker appears only within a carousel, but the query override works even after a handpicked Query Loop is moved outside one.

**Tech Stack:** WordPress 6.6+, PHP 8.2+, TypeScript/React, Gutenberg `@wordpress/*` packages already installed, Jest/Testing Library, PHPUnit/Brain Monkey, Embla (unchanged).

**Embla reference:** [Embla docs](https://www.embla-carousel.com/docs) and, specifically, [v8.6.0 docs](https://www.embla-carousel.com/docs/v8), [methods](https://www.embla-carousel.com/docs/v8/api/methods) and [events](https://www.embla-carousel.com/docs/v8/api/events). This plugin pins Embla 8.6.0; the unversioned docs currently describe v9 RC, so implement and verify against v8 semantics. `slideNodes()` reports actual rendered slides, `scrollSnapList()` reports navigation positions, and `reInit` refreshes an initialized instance when slide DOM changes. Reuse existing carousel lifecycle; do not introduce a second instance.

## Global Constraints

- No changes to carousel setup steps, saved carousel markup, navigation, dots, scrolling, autoplay, or card presets.
- One post type per carousel; at most 20 selected IDs. Disable adding after 20 picks, with an accessible limit message; enforce the same cap when reading stored IDs.
- Show at most five published post suggestions for the selected type, both before typing (five latest) and after each keyword search. This limits suggestions, not the selected-post list or carousel slides.
- Published content only, including for logged-in administrators. Resolve stored IDs at display time: deleted, trashed, draft, private, or wrong-type IDs produce no slide in either view; surviving posts close up in the saved order. Keep stale IDs in saved metadata until an editor removes them, so removing one does not silently rewrite the selection.
- Latest mode is default whenever metadata is absent; do not rewrite existing Query blocks on load.
- Use core editor components and accessible labels for keyboard-operated add/remove/move controls.
- Jest, PHPUnit, ESLint, Stylelint, `tsc --build --noEmit`, PHPCS and PHPStan must show no new failures relative to baseline.
- Browser verification and human-vs-agent attribution in PR description are release gates, not assumptions of this plan.
- Run browser end-to-end checks against local WordPress Playground, started from this plugin root with `npx @wp-playground/cli@latest server --auto-mount --login --php=8.2` after `npm run build`. Check Node.js ≥20.18; verify the plugin is active in the Playground editor. Playground is ephemeral, so recreate fixture posts/pages for each fresh server session.

**Stored shape:** `core/query.attributes.metadata.rtCarousel` is `{ mode: 'latest' | 'handpicked', ids: number[], postType: string }`. Missing metadata means Latest. `postType` records the type when the selection was last edited; change of `query.postType` to another type clears IDs in either mode. Preserve unrelated metadata keys on update. Do not copy IDs into `query`, where native controls or REST requests could interpret them.

**Stale IDs:** The stored list is selection intent, not a guarantee that every post still exists. On each front-end render, query only published posts of the selected type with `post__in` and `orderby=post__in`; WordPress drops missing/non-published IDs without gaps, and `core/post-template` returns empty HTML when none remain. On each editor preview query, request the same published/type-restricted IDs, order by `include`, and let core Post Template render surviving cards. When all IDs are missing or unpublished, show an editor-only “No selected published posts are available” prompt rather than silently showing Latest posts. Show unresolved picks as “Unavailable post (ID …)” in the picker with an accessible Remove button; do not silently purge IDs. A stale ID still counts toward the 20-pick limit until removed.

**Server hook signatures:** `filter_handpicked_block_data( array $parsed_block ): array` receives parsed `core/query`; `filter_handpicked_query_vars( array $query_vars, \WP_Block $block, int $page ): array` receives `core/post-template` via `query_loop_block_query_vars` (`build_query_vars_from_query_block()` in WP 6.6 passes exactly these three arguments). Use `metadata.rtCarousel` during the first hook to set `query.inherit = false` and attach the pick data in an internal query-context key; second hook acts only when that key is present. The internal key is render-time only. First hook must not mutate serialized content, other blocks, or Latest queries.

**Editor contract:** Query edit wrapper reads its `attributes.query.postType` (default `post`) and selected metadata. Post Template wrapper uses existing block-editor selectors `getBlockParents(clientId)` and `getBlock(id)` to locate nearest `core/query` ancestor, reads that Query block's metadata, and passes a modified `context.query` prop only in Handpicked mode. WordPress 6.6 Post Template consumes `context.query`; its normal block controls, `BlockContextProvider` and Post Template inner blocks remain in use. For no picks, render an editor-only accessible prompt instead of core's fallback/latest preview. The override must not depend on carousel ancestry or the continued presence of a carousel in the post; ensure the editor enhancement still loads after moving the only carousel out of the document.
